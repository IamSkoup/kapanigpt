# KapaniGPT

Исходный код KapaniGPT — русскоязычного ИИ-чата с авторизацией Firebase, историей сообщений, настройками, несколькими профилями моделей, системой лимитов, внутренними токенами и пробным Kapani AI plus.

Текущая публичная версия приложения работает на [kapanigpt.netlify.app](https://kapanigpt.netlify.app/). Адрес [iamskoup.github.io/kapanigpt](https://iamskoup.github.io/kapanigpt/) перенаправляет на Netlify. Этот репозиторий содержит код приложения, но не копию пользовательских аккаунтов, базы данных или серверных секретов.

## Запуск для разработки

Нужны Node.js 22.13 или новее, npm и настроенная база PostgreSQL. Установи зависимости с `npm ci`, затем запусти `npm run dev`. Для сборки используется `npm run build`. Firebase-проект, Netlify Database, миграции и переменные окружения настраиваются отдельно.

Серверные маршруты находятся в `app/api/`. Они отвечают за ИИ, учёт лимитов, подписки, пробный период и безопасность операций. Веб-интерфейс находится в `app/` и `components/`.

**Важно о хостинге.** GitHub Pages не запускает Next.js API-маршруты и PostgreSQL, поэтому в `docs/index.html` размещено только перенаправление на Netlify, а не копия приложения. Сам ИИ-чат работает на Netlify с серверной базой данных.

Авторская расширенная база знаний заменена в `lib/master-prompt.md` нейтральным шаблоном. В публичную копию намеренно не вошли личные истории людей и внутренние данные живого проекта. Для собственной установки используй свой текст.

Автор проекта — Кайон.


## Интернет-поиск

KapaniGPT автоматически решает, нужен ли для вопроса веб-поиск. Серверный `/api/chat` получает до пяти результатов и передаёт модели только заголовки и короткие выдержки. Серверные источники показываются отдельно в интерфейсе и сохраняются в истории. Для Brave Search можно добавить `BRAVE_SEARCH_API_KEY` в переменные окружения Netlify (никогда не в `NEXT_PUBLIC_*` и не в Git). Без ключа сервер пробует RSS Bing. Резервный поиск не гарантирован, поэтому при его недоступности модель должна честно сообщать, что актуальные источники не получены. Таймауты и объём поиска ограничены.

## Вложения и генерация изображений

В обычном чате можно прикреплять JPEG, PNG, WebP и текстовые файлы (.txt, .md, .json, .csv, исходный код). Клиент сжимает фото и передаёт текущие изображения в Kilo AI через сервер; для распознавания используется бесплатная мультимодальная модель `nvidia/nemotron-3.5-super-vl:free`. У текстовых файлов передаются части содержимого до 6000 символов на файл; если текст длиннее, запрос содержит отметку о фрагменте. Бинарные PDF/DOCX пока не поддерживаются, не стоит переименовывать их в TXT. Вложения с изображениями попадают во внешний бесплатный сервис; перед отправкой следует учитывать его политику хранения данных.

Генерация полноцветных PNG/JPEG **не подключена**, потому что на новом хостинге нет настроенного провайдера растровых изображений. Вместо фальшивого «изображение готово» модель может создать SVG-иллюстрацию как настоящий файл, который показывается прямо в чате и скачивается. Для генерации растровых файлов требуется отдельный API, настроенный серверно; ключи никогда не добавляются в публичный репозиторий.

## Частная база знаний Капаней

Подробный оригинальный master prompt хранится только в таблице `ai_site_settings` PostgreSQL, в записи `master_prompt`. Приложение **не** включает приватные биографии и личные истории в публичную сборку. Если запись отсутствует, чат сообщает, что закрытая база не найдена, вместо выдумывания сведений. Полные тексты больших абзацев больше не пропускаются целиком, а разбиваются на фрагменты для подбора по запросу.

Для восстановления оригинала владелец может в Netlify добавить переменную окружения `KAPANIGPT_OWNER_UID`, равную **UID его собственного подтверждённого аккаунта Firebase Authentication** (без префикса `fb:`). После этого в «Настройки → Персонализация» для этого аккаунта появится возможность загрузить оригинальный файл `.txt` или `.md` (100–180000 символов). Данные передаются в защищённый `PUT /api/knowledge`, который сравнивает UID из проверенного Firebase ID token с серверной переменной. Публичный `GET /api/knowledge` возвращает авторизованным пользователям только состояние и размер базы, но **не её содержимое**. Для других пользователей запись запрещена, а при отсутствии переменной доступ на изменение закрыт у всех. Загрузка файла заменяет запись в PostgreSQL, не добавляя частный канон в GitHub.

## Дерзкая манера общения

В «Настройки → Персонализация → Манера общения» доступен режим «Дерзкая, с матами». Он добавляет живой сарказм, резкую реакцию на троллинг и уместную ненормативную лексику, не отменяя фактическую помощь. На серьёзные и чувствительные темы ассистент отвечает без грубости. Выбранный режим сохраняется отдельно для Firebase-аккаунта, другие манеры общения остаются доступными.

## Восстановление оригинального канона

При переезде на новую базу данных Netlify запись `ai_site_settings.master_prompt` может отсутствовать. Репозиторий **не содержит** оригинальный закрытый мастер-промпт. Ни GitHub Pages, ни публикация в `main` сами его в PostgreSQL не вставят.

Владелец может восстановить запись без публичной публикации текста через персонализацию в приложении, предварительно указав `KAPANIGPT_OWNER_UID` в настройках окружения Netlify. UID можно скопировать непосредственно из раздела «Знания о Капанях». После настройки UID и обновления деплоя в этом же разделе появится кнопка импорта `.md`/`.txt`; после загрузки статус покажет число символов в сохранённой базе.

Альтернативный способ для администратора с прямым доступом к PostgreSQL и локальному файлу.

```sh
DATABASE_URL='postgresql://...' node scripts/restore-private-knowledge.mjs ./KAPANIGPT_MASTER_PROMPT_v2.md
```

Никогда не хранить настоящий `DATABASE_URL`, оригинальный файл с частным каноном и дампы `.sql` в публичном репозитории. Если исходный мастер-файл у владельца утерян, сначала следует восстановить его из личной копии, а не сочинять биографии участников с нуля.


## Восстановление базы и дефолтный стиль (обновление)

Начиная с новой версии, KapaniGPT стартует с манерой общения «Дерзкая, с матами». Ранее сохранённые значения `balanced` из старой схемы воспринимаются как прежний неявный дефолт и переходят на «Дерзкая»; если человек вручную переключит на «Обычная», этот осознанный выбор сохраняется отдельно в базе под значением `plain` и затем отображается как «Обычная».

При отсутствии `ai_site_settings.master_prompt` больше нет полной амнезии: в `lib/kapani-public-lore.ts` лежит краткий, безопасный для публичной публикации справочник художественного мира. Это **не** полная приватная база и не воспроизводит личные данные из оригинального мастер-файла.

Для восстановления именно полного канона в собственном аккаунте открой «Настройки → Персонализация» и выбери «Восстановить полный канон в моём аккаунте (.md или .txt)». Импорт использует `/api/knowledge/personal`, проверяет Firebase ID token на сервере и записывает в PostgreSQL приватный ключ `user_kb_<SHA256(firebase user id)>`. Ни UID владельца, ни переменная `KAPANIGPT_OWNER_UID` для **личного** восстановления больше не нужны. Другой пользователь не получает этот мастер-файл через API, но его текст по соответствующим запросам будет отправляться внешнему ИИ-провайдеру для генерации ответов. Для общей базы для всех пользователей прежний защищённый механизм с серверным UID остаётся доступен владельцу. Базу следует импортировать только с правом использования содержащихся в ней сведений.

**Важно:** отправка кода в GitHub не изменяет содержимое работающей PostgreSQL сама по себе. До загрузки личного файла доступен только сокращённый встроенный канон, а полная база считается не восстановленной.
